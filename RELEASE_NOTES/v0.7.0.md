ollanet 0.7.0 adds `ollanet serve`, a read-only model catalog for agents off your network, plus quieter output for scripts and agents and clearer scan failures.

## Highlights

- **`ollanet serve`**: a token-gated, read-only catalog of the models on your hosts, for agents that are not on your network. It binds to `127.0.0.1:11500` by default, and `--funnel` can publish it through Tailscale Funnel. It never returns hostnames, IPs, ports, OS, or paths, and it never runs prompts, pulls, or deletes.
- **`-q` / `--quiet`** on every command (or `OLLANET_QUIET=1`): results on stdout, stderr only for errors and warnings.
- **`--stdin` / `-`** for `prompt` and `compare`: waits for stdin to close and uses it as the prompt, for slow producers such as `git diff` on a large repo. Without the flag, piped stdin is still used only if it arrives within 100ms, so agent and CI pipes that never close do not hang (unchanged since 0.6.22).

## Changes by command

### scan

- Lists the hosts that were probed but did not answer as Ollama, with a reason: `timeout after 2500ms`, `connection refused (ECONNREFUSED)`, `HTTP 404, no /api/tags (not Ollama?)`. Offline Tailscale peers shown with `--all` collapse to a count.
- `--json` failures keep `name`, `ip`, and `error` and add `port` and a short `code`: `timeout`, `refused`, `reset`, `unreachable`, `dns`, `http`, `not-ollama`, `offline`, or `error`. The library exports the `ScanFailureCode` type.
- IPv6 hosts get bracketed endpoints (`http://[addr]:11434`). Before this fix, scan produced invalid URLs for them.
- Help for `--all` now says what it does: offline Tailscale peers are listed as offline, not probed. The MCP `ollanet_scan` description says the same.

### prompt

- `--stdin` / `-` waits for stdin to close and uses it as the prompt.
- `-q` prints only the reply on stdout: no host line, chat id, continue hint, or stats.

### compare

- The result table now prints on stdout, as `bench` already did. Saved paths and the default-prompt notice stay on stderr.
- The default-prompt notice prints before the run, not after.
- `--stdin` / `-`, as for `prompt`.
- `→ model (1/2)` progress lines print only when stderr is a terminal.

### bench

- Progress lines print only when stderr is a terminal.
- `-q` drops the plan and progress lines.

### serve (new)

- `ollanet serve [--listen <host:port>] [--refresh <interval|off>] [--rate <n>]`. Endpoints: `GET /healthz` (no auth) and `GET /v1/catalog` (`Authorization: Bearer <token>`). The catalog starts from the last saved scan and re-scans every 10 minutes by default. Each token gets 60 requests per minute by default.
- `serve token add <name> [--expires <duration>]`, `token list [--json]`, `token rm [name]`, `token prune`.
- `token list` shows when each token was last used. A running server records a token's first use right away, later uses at most once a minute, and anything still pending at shutdown.
- `token rm` with no name, in a terminal, lets you pick tokens from a numbered list (`1,3`, `2-4`, `all`) and confirm with y/N. Without a terminal it exits with usage and does not prompt.
- `token prune` with no flags removes tokens that are expired or unused for 30 days (never-used tokens count from creation). `--expired` and `--unused-days <n>` narrow or change that. It lists what it will remove and asks first; `--yes` skips the prompt and is required without a terminal.
- `serve label set|rm|list` sets the opaque label a host is shown under. Without one, the label is the first alias for that machine, else `host-1`, `host-2`, and so on.
- `serve --funnel [--funnel-port 443|8443|10000] [--keep-funnel]` publishes through Tailscale Funnel after checking `tailscale status --json` (MagicDNS, HTTPS certificates, Funnel attribute). If the Funnel attribute is not approved, it prints Tailscale's approval link and exits. On exit it turns off only the port it added.
- `serve status` shows the local and Funnel URLs of the running server.

### help

- `ollanet help` is shorter: what ollanet does, the safety note, usage, and eight examples. `ollanet help <command>` (or `ollanet <command> --help`) has every flag and more examples.

### config

- The checkout no longer tracks `config.json`. It is gitignored, and `config.example.json` is the starting point. Installed copies (`~/.ollanet/config.json`) are not affected.
- New environment variables: `OLLANET_QUIET`, `OLLANET_PROGRESS`, `OLLANET_SERVE_FILE` (default `~/.ollanet/serve.json`), and `OLLANET_TAILSCALE_BIN`.

### mcp

- With `-q`, the startup banner on stderr is dropped. The tools are unchanged.

## Upgrade notes

- **Back up a checkout's `config.json` before you pull.** It is no longer tracked. If yours is unchanged from the committed copy, the pull deletes it. If you edited it, git refuses the pull until you move it aside. Copy it somewhere safe, pull, then put it back as `config.json`, or start again from `config.example.json`. Installs from npm are not affected.
- **The compare table moved from stderr to stdout.** Scripts that captured it from stderr should read stdout instead. `--json` is unchanged.
- **Progress lines print only on a terminal.** `compare` and `bench` no longer print `→ model (1/2)` lines when stderr is piped or captured. Set `OLLANET_PROGRESS=1` to force them on, or `0` to turn them off on a terminal.

## Security notes for serve

- **Loopback by default.** `serve` binds `127.0.0.1:11500` and refuses a non-loopback `--listen` unless you pass `--allow-remote`. Publish it with `--funnel` or `tailscale serve`, which add TLS.
- **Hashed tokens.** A token is printed once at creation. `serve.json` stores only its SHA-256 hash, plus creation, expiry, and last-use times. Comparison is constant-time, expired tokens never match, and a failed request always gets the same `401` body. Access logs name the token, never its value.
- **Read-only.** The catalog has only allow-listed model fields (name, size, parameter size, quantization, family, capabilities) under opaque host labels. It never includes hostnames, MagicDNS names, IPs, ports, OS, endpoints, scan failures, or file paths, and it does not proxy prompts, compares, pulls, deletes, or `ps`.
- **Funnel is public.** `--funnel` puts the catalog on a public `https://<device>.<tailnet>.ts.net/` URL. It refuses to start until at least one token exists, it never runs `tailscale funnel reset`, and it does not replace a port that already serves something else. Use `--expires` on tokens you share.
- **Prune old tokens.** `ollanet serve token prune` removes expired tokens and tokens unused for 30 days, after you confirm. `token list` shows each token's last use, so you can see which ones are still active.
